# gaokao-audit · 高考志愿方案审计器

**只审计，不生成。**

给一份高考志愿表 + 一个提问，检查表里的数据和逻辑是否自洽，返回**带证据**的报告。

> 它不回答「你该怎么填」，它回答「**你这份表里，哪些条目的依据对不上**」。

## 为什么是"审计"而不是"推荐"

2026 年 AI 志愿填报已是大流量场景，但多篇独立横评实测暴露了一批**系统性错误**：
用错年份的一分一段表（位次前拉约 2440 名）、把录取线抄错（582 vs 官方 548）、
把"位次比最低位次还靠后"的专业放进"稳"档……

**这些错误的共性不是"模型不够聪明"，而是"它说的数字和它自己的逻辑对不上"** ——
而这类错误**是可判定**的，所以可以审计、可以评测。**生成方案则无法评测，边界就划在这里。**

## ⚠️ 它**也能**推荐 —— 但请先读这一段

除了审计，它还能生成一份推荐（`POST /recommend`）。**而且它是有回测的** ——
这是它和"又一个 AI 填志愿"的区别。**但回测的数字不好看，我照实放在这里：**

```
参照年 2022 → 检验年 2025，40 个考生视角
录取率（推荐的条目里他能上的占比）: 0.355
浪费位次 P50 / P90               : 14443 / 30543
```

**为什么这么低**：不是模型不行，是**用单一年份当参照这件事本身不够** ——
2022→2025 各专业组录取位次整体漂移，而 **2023/2024 的数据恰好缺失**。
详见 [`docs/BACKTEST.md`](docs/BACKTEST.md)，那里也写了**没有跑对照基线**
（所以现在说不清模型到底贡献了什么）。

> **结论：推荐这个功能有评测、能跑通、也敢报出不好的数字 —— 但它还不到能上简历的程度。**
> 审计（下面的部分）才是这个项目现在真正能拿得出手的东西。

**它的闭环是这样的**：

```
考生信息 → 确定性筛选（0 LLM）→ LLM 排序组合 + 说理由 → 生成的方案喂回审计器自审
```

**自审那一步是它的价值所在**：我生成一份方案，**然后用我自己的审计器审它** ——
`tests/test_recommend_flow.py` 里有对照测试（干净生成 = 0 发现；故意标错档位 = 被抓）。

## 它检查什么

| 检查 | 抓什么 |
|---|---|
| `rank_conversion` | 位次是不是用**别的年份**的一分一段表算的（能指名道姓说是哪一年） |
| `admission_line` | 表里声称的投档线跟真实值对不上 |
| `tier_logic` | 标着"稳/保"，但位次其实**够不着** |
| `subject_plan` | 考生选科不满足该专业组的要求 |
| `adjacent_group_verify` | （追加）判"够不着"时，同校相邻组是否够得着 —— **可能是组号读错了** |

## 实测数字（`docs/EVAL.md`）

```
干净表基线误报 : 0        检出率 recall   : 0.905
精确率 precision: 0.963    （60 条志愿 × 每类注入 50 个已知错误）
```

评测方式是**错误注入 + 真实 badcase**：往干净表里塞进**已知**的错误，数抓到了几个。
badcase 用的是公开横评里记录过的**真实**错误，不是自己编的题。

⚠️ `docs/EVAL.md` 里有专门的「**已知抓不到**」一节 —— 一版"全部抓到"的报告反而不可信。

## 怎么跑

```bash
py scripts/build_db.py      # CSV → SQLite（只灌 广东/2021-2025/本科批）
py -m pytest -q             # 132 个测试（全程离线，走缓存）

# 起服务
cp .env.example .env        # 填 DEEPSEEK_API_KEY
py scripts/serve.py         # 后端 → 127.0.0.1:8000

# 前端
cd frontend && npm install && npm run dev
```

**重新生成演示资产**（会真调一次模型，之后走缓存）：

```bash
py scripts/make_demo.py
```

## 数据

- 来源：`Gaokao-Compass-11M`（Hugging Face），经 `hf-mirror.com` 下载
- 范围：**广东省 · 本科批**

> ⚠️ **数据覆盖不完整，且这是已知边界**：2023 年本科批录取数据整张缺失、2024 年只有专科批，
> 2021 年一分一段表的科类/批次字段全空。
> 各检查项**实际可用的年份**见 [`docs/data-schema.md`](docs/data-schema.md)。

## 已知边界（要主动说）

- **数据只覆盖广东 + 有限年份**；长尾院校（地方/职业院校）必有缺口
- **不做价值判断** —— 不回答"你该不该报这个专业"
- **`/example` 与演示报告走缓存**，所以离线可复现；但**新截图**要真调模型
- **护栏是进程内内存 + 一把锁** —— 多实例部署要换成共享存储
- 单次请求的 LLM 调用**上限 4 处**（截图解析 / 意图分类 / supervisor / 报告），
  其中 supervisor 在**无异常时根本不调**

## 目录

```
src/gaokao_audit/
├── checks/        四个确定性检查（+ 一个追加检查）—— 零 LLM
├── llm/           DeepSeek 客户端、缓存、4 处调用的提示词与 schema
├── pipeline/      截图解析 / 意图分类 / supervisor / 报告 / LangGraph 编排
└── api/           FastAPI 服务 + 成本护栏
eval/              错误注入 + 真实 badcase + 评测 harness
frontend/          Vite + React + TS + Tailwind
docs/              数据 schema、评测报告、多模态验证结论
scripts/           build_db / serve / make_demo / check_vision
```
